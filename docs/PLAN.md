## 0. 제품 정의

**포지셔닝 한 줄**
> "50대에도 부담 없이, 하루 한 장면만 따라 말해 보는 일본어 회화 앱."

| 비교 | Duolingo | 만능일본어 | HelloTalk | NHK Easy | **하루 일본어 대화** |
|---|---|---|---|---|---|
| 주 타깃 | 10~30대 | 독학 전반 | 회화 교류 | 중급 읽기 | **50대 취미 학습자** |
| 학습 단위 | 레벨 업 미션 | 단어/문법 사전 | 상대와 채팅 | 뉴스 기사 | **하루 1개 대화** |
| 진입장벽 | 게이미피케이션 과다 | 정보 과다 | 상대 필요 | 문장 김 | **가입 없이 바로 시작** |
| 비용 | 부분 유료 | 부분 유료 | 부분 유료 | 무료 | **완전 무료** |
| 말하기 | 일부 | 거의 없음 | 상대 의존 | 없음 | **따라 말하기 중심** |

**차별화 5가지**

1. **모드 선택제** — "오늘은 상점 주인 모드로 해볼까?"처럼 학습자가 장면을 고름
2. **1개 기본 원칙** — 10문장을 강요하는 대신 1개로 성공 경험을 만듦
3. **50대 친화 UI** — 큰 글씨(18~28sp, 기본 22sp), 1배속 고정, 한 화면에 한 일
4. **로그인 無, 광고 無** — 휴대폰 켜듯 바로 열고 바로 닫기
5. **오프라인 완결** — 비행기·지하철에서도 동일하게 동작

**검증 가설 3개 (무료 모델이므로 지표는 리텐션 중심)**

| 가설 | 실험 | 성공 기준 |
|---|---|---|
| "1개만 해도 충분하다"가 이탈을 줄인다 | 기본 1개 / 3개 그룹 비교 | 1개 그룹 D7 리텐션 +15%p |
| 모드를 고르는 행위가 애정도를 높인다 | 온보딩에서 모드 선택 vs 랜덤 | 7일 내 모드 재변경률 40% 이상 |
| 후리가나가 작으면 읽히지 않는다 | 16sp(가나 7sp) vs 22sp(가나 13sp) | 기본 22sp로 상향, 가나 비율 0.58 |

## 2. MVP 기능 (MoSCoW)

| 우선순위 | 기능 | 왜 필요한가 | 최소 구현 범위 |
|---|---|---|---|
| **Must** | 대화 모드 선택 (**기본: 일반인**) | 페르소나의 핵심 니즈 | 온보딩 + 우측 상단 `MODE` 텍스트에서 6개 모드 변경 |
| **Must** | 오늘의 대화 1개 제공 | "1개 원칙"의 핵심 | 기본 1개, 설정에서 1/3/5 선택 |
| **Must** | 듣기(TTS, 1배속 고정) | 입이 나오려면 귀가 먼저 | 속도 옵션 없이 1.0x 재생 |
| **Must** | 따라 말하기(녹음·재생) | 제품 정체성 | 녹음 → 내 목소리 다시 듣기 |
| **Must** | 뜻 + 로마자 보기 | 50대 학습자 필수 | 기본 표시, 토글로 숨기기 |
| **Must** | 완료 체크 + 연속일 | 다음 날 다시 오게 | 날짜 기록만, 압박 없는 문구 |
| **Should** | 아침 알림 | 복귀 유도 | 1일 1회, 끄기 쉬움 |
| **Should** | 복습 화면 | 7/14/21/30일 복습 | 지난 7일 완료 목록 |
| **Could** | 발음 채점 | 동기부여 | 점수 대신 "비슷해요/한 번 더"만 |
| **Won't (이번엔)** | AI 자유대화, 구독, 광고, 로그인, 랭킹, 친구, SNS, 서버 동기화 | 무료·오프라인 원칙과 충돌 또는 과공수 | — |

> **무료 모델 결정:** 수익 지표 대신 **학습 완료율 · D7 리텐션**을 성공 지표로 씁니다. 콘텐츠를 앱에 번들하므로 서버 비용이 없어 무료 유지가 가능합니다.

## 3. UX/UI 설계 (50대 친화)

### 화면 트리

```
앱 실행 (로그인 없음)
├─ 온보딩 (3장, 건너뛰기 가능)
│   ├─ "외우지 않으셔도 돼요"
│   ├─ 모드 고르기 ← [일반인 추천] 기본 선택
│   └─ 하루 개수 고르기 ← [1개 추천] 기본 선택
└─ 홈 [대화]
    ├─ 대화 연습 (A/B 대화 통째로 보기 → 듣기 → 따라 말하기 → 내 목소리)
    ├─ 모드 변경 (우측 상단 MODE, 언제든 변경)
    ├─ 복습 (지난 7일)
    ├─ 기록 (연속일)
    └─ 설정 (속도 / 글자 / 개수 / 알림)
```

### 첫 3분 클릭 흐름

1. 앱 실행 → 바로 홈 (온보딩은 첫 실행만)
2. 상단에 **"일반인"** 칩 → 누르면 모드 변경 시트
3. "오늘의 대화" 말풍선(한 편만 표시): A(왼쪽 연회색) `おはようございます。` / B(오른쪽 연두색) `おはようございます。` / A `いいお天気ですね。` / B `はい、いいお天気ですね。` + 아래에 한국어 뜻과 한자 위 후리가나
4. ◀ 이전 대화 / 다음 대화 ▶ 로 해당 모드의 대화를 자유롭게 넘겨 봄 (하루 1편 제한 없음, 진도 문구 없음)
5. 한 줄 아이콘(🔊 전체 듣기 → 1배속, 🎤 따라 말하기, ▶ 내 목소리)으로 연습
6. 오른쪽 아래 작은 원형 메뉴(48dp) → 팝업 사이드바에서 메인/복습/설정/종료 선택
7. "학습 종료하고 앱 닫기" → 기록 저장 후 앱 종료 (약 2분)

### 50대 배려 디자인 원칙

| 항목 | 기준 |
|---|---|
| 본문 글자 | 18~28sp(기본 22sp), 제목 26sp / 후리가나는 본문의 0.58배 |
| 터치 영역 | 48dp 이상 (플로팅 메뉴 48dp, 아이콘 버튼 60dp) |
| 화면 이동 | 상단 버튼 대신 팝업 사이드바(메인/복습/설정/종료) |
| 기본 테마 | 밝은 테마 기본(고대비), 다크모드 선택 |
| 재생 속도 | **1.0x 고정** (옵션 없음) |
| 기본 표시 | 한자 위 후리가나(작은 가나) + 한국어 뜻 항상 보임 (한글 발음 표기는 숨김) |
| 피드백 | 틀려도 빨간색 금지. "한 번 더 들어볼까요?" |
| 문구 | "외우세요" ❌ → "따라 말해 보세요" ⭕ |

**이탈 위험 3곳 + 개선**

| 지점 | 개선 |
|---|---|
| 모드 고르다 멈춤 | **일반인을 기본 선택**해 두고, 변경은 언제든 |
| 녹음 권한 거부 | 권한 설명 후, 거부해도 "듣기만 완료" 허용 |
| 다음 날 안 옴 | "어제의 대화 다시 듣기"를 홈에 노출 |

## 5. 기술 설계 (Android)

**아키텍처:** MVVM + UseCase, 단일 모듈. 수동 DI(`AppContainer`)로 Hilt 없이 시작.

```
app/src/main/java/com/haru/nihongo/
├─ HaruNihongoApp.kt / MainActivity.kt
├─ di/AppContainer.kt
├─ domain/
│   ├─ model/Models.kt          (Mode, Utterance, Dialogue, Settings)
│   └─ usecase/                 (DailyPicker, GetTodayDialogueUseCase)
├─ data/
│   ├─ content/ContentDataSource.kt  (assets JSON + kotlinx.serialization)
│   ├─ local/ProgressDao.kt     (Room)
│   ├─ preferences/SettingsStore.kt  (DataStore)
│   └─ repository/LearningRepository.kt
├─ audio/VoicePracticeController.kt  (TTS + MediaRecorder + MediaPlayer)
└─ ui/
    ├─ theme/Theme.kt
    ├─ common/DialogueCard.kt
    ├─ onboarding/OnboardingScreen.kt
    ├─ today/  (TodayScreen, TodayViewModel)
    ├─ review/ReviewScreen.kt
    ├─ settings/SettingsScreen.kt
    └─ AppNavHost.kt
```

**데이터 모델 (ER 요약)**

```
Mode(일반인 기본) ← Dialogue(order) ← Utterance(ja, ko, romaji, polite, tip)
Progress(date, completedCount, listened, recorded)
Settings(mode=GENERAL, dailyCount=1, fontSize=16, alarm)
```

**오프라인 전략:** 콘텐츠 JSON을 앱에 번들 → 파싱해서 메모리에 보관 → 학습 기록만 Room/DataStore. **서버·계정·동기화 없음.**

**발음 관련 구현 옵션**

| 옵션 | 정확도 | 오프라인 | 비용 | 결정 |
|---|---|---|---|---|
| 녹음 → 내 목소리 재생 | – | ✅ | 0 | **MVP 채택** |
| Android `SpeechRecognizer` | 중 | ❌ | 0 | 보류 |
| ML Kit 음성 인식 | 중상 | 부분 | 0 | 이후 검토 |
| 외부 발음 API | 상 | ❌ | 유료 | **무료 모델이라 탈락** |
| 앱 번들 사전 + `InlineTextContent` 후리가나 | 대화 한정 | ✅ | 0 | **MVP 채택** (한자 위 작은 가나) |

**기술 리스크 3개**

1. TTS 품질 기기 편차 → 1배속 고정 + 문장별 발음 팁 제공
2. 녹음 권한 거부 → "듣기만으로 완료" 대체 경로 필수
3. 날짜/타임존 → `LocalDate` 기준 단일 처리

## 6. 앱 내 튜터 시스템 프롬프트 (모드 반영)

> 자유대화는 MVP 제외. "한 번 더 말해 보세요" 문구 생성·추후 확장용.

```
당신은 "하루 일본어 대화"의 일본어 튜터입니다.
[현재 모드]: {mode}   (기본: 일반인)
[현재 상황]: {situation}
[학습자]: 50대 취미 학습자, N5~N4

규칙:
1. 한국어로 설명하되, 예시 문장은 일본어로만 씁니다. 영어 금지.
2. 일본어 문장은 한 번에 1개, 15자 이내.
3. 로마자 읽기를 괄호로 함께 표기합니다.
4. 틀려도 빨간 표시·"틀렸습니다" 금지. "이렇게도 말할 수 있어요:" 로 보여줍니다.
5. 매 턴 끝에 "한 번 더 따라 말해 보세요." 를 붙입니다.
6. 선택한 모드의 말투(존댓말/반말)를 벗어나지 않습니다.

시작: {mode에 맞는 인사말}
```

## 7. 리텐션 & 성공지표 (무료 확정)

| 지표 | 정의 | 목표 |

| 일일 완료율 | 열었을 때 대화 완료 | 80% |
| 모드 변경률 | 7일 내 모드 재선택 | 40% |

**스트릭 끊김 처리 3가지 비교**

| 방식 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 초기화 | 긴장감 | 50대에게 죄책감 ⚠️ | 탈락 |
| 숨김 | 부담 없음 | 동기 약함 | 탈락 |
| **"어제도 잘했어요" 유지** | 부담 없음 + 복귀 유도 | – | **채택** |

**알림 문구 5개 (1일 1회, 끄기 쉬움)**

1. "오늘의 대화가 기다리고 있어요. 😊"
2. "어제의 `こんにちは`, 다시 들어볼까요?"

4. "딱 2분이면 돼요."
5. "외우지 않아도 괜찮아요. 대화 통째로 따라 해 보세요."

> 수익 지표는 의도적으로 제거. "오늘도 해냈다"는 경험을 지표로 삼습니다.
